<task type="auto">
  <name>Implement LoadJobHandler</name>
  <files>src/jobs/handlers/load.rs</files>
  <action>
Create src/jobs/handlers/load.rs implementing the JobHandler trait for data loading:

**Structure:**
- LoadJobHandler struct with LoadedDaysRepository and ChunkGenerator fields
- LoadJobPayload and LoadJobResult structs for type-safe JSON handling
- JobHandler trait implementation with job_type() returning JobType::Load

**execute() method logic:**
1. Parse payload (start_date: "YYYY-MM-DD", days: i64) using serde_json
2. Parse start_date to NaiveDate with chrono::NaiveDate::parse_from_str
3. Call LoadedDaysRepository::get_missing_dates(start_date, days) to find gaps
4. For each missing date:
   - Generate chunk via ChunkGenerator::generate_chunk(date)
   - Save to database via ChunkGenerator::save_chunk_to_db(&chunk)
   - Mark as loaded via LoadedDaysRepository::mark_day_loaded(date, 1440, Some(job.id))
   - Track per-day statistics (positions, aspects, lunar_conditions counts)
5. Calculate already-loaded dates for "skipped" reporting
6. Return LoadJobResult as JSON with:
   - start_date, days_requested
   - dates_loaded (count and per-date details)
   - dates_skipped (already loaded)
   - dates_failed (with error messages)
   - total_positions, total_aspects, total_lunar_conditions

**Error handling:**
- Per-date failures don't fail entire job — track in failed list
- Job only fails if NO dates could be processed
- Include error details in result JSON for troubleshooting

**Performance notes:**
- Process days sequentially (Swiss Ephemeris thread safety)
- spawn_blocking already handled by JobExecutor
- Each day is independent transaction (handled by save_chunk_to_db)

Reference 06-RESEARCH.md LoadJobHandler example code for implementation patterns.
