Extend src/cli/app.rs to add the Load subcommand:

**Add to Commands enum:**
```rust
/// Load planetary data for a date range
Load {
    /// Start date (YYYY-MM-DD)
    #[arg(long, value_name = "DATE")]
    start: String,

    /// Number of days to load (1-365)
    #[arg(long, value_name = "N")]
    days: i64,

    /// Execute synchronously and wait for completion
    #[arg(long)]
    sync: bool,
},
```

**Add to App::run() match statement:**
1. Parse and validate date format with NaiveDate::parse_from_str("%Y-%m-%d")
2. Validate days is between 1 and 365 (inclusive)
3. Create database pool using existing pool creation pattern (check how other db features do this)
4. Create JobRepository, LoadedDaysRepository
5. Create LoadJobHandler and register with JobExecutor
6. Build payload JSON: {"start_date": "YYYY-MM-DD", "days": N}
7. If sync flag:
   - Call executor.execute_sync(JobType::Load, payload).await
   - Display result: dates loaded, skipped, failed counts
   - Display any errors from failed dates
8. If not sync:
   - Call executor.execute_async(JobType::Load, payload).await
   - Display job-id and poll URL (/api/v1/jobs/{job-id})

**Error handling:**
- Invalid date format: descriptive error message
- Days out of range: descriptive error message  
- Database connection failure: propagate error
- Job execution failure: display error details

**Output formatting:**

- Async mode: job-id and polling instructions
