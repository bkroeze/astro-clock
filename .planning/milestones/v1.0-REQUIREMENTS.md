## v1 Requirements (All Complete)

### Chart Generation (Existing)

- [x] **CHART-01**: User can generate chart for current time with default location
- [x] **CHART-02**: User can specify custom date, time, and location
- [x] **CHART-03**: Chart renders as PNG image with zodiac wheel
- [x] **CHART-04**: Chart renders as WebP image
- [x] **CHART-05**: Chart outputs as Markdown table with positions
- [x] **CHART-06**: User can select from 11 house systems
- [x] **CHART-07**: Chart displays planetary aspects (conjunctions, oppositions, etc.)

### HTTP Server (Existing)

- [x] **SRV-01**: Server mode provides HTTP endpoint for chart generation
- [x] **SRV-02**: Endpoint accepts lat/lon/time query parameters
- [x] **SRV-03**: Endpoint returns PNG image directly

### Database Schema (Phase 1)

- [x] **DB-01**: Create aspect_summaries table for pre-aggregated aspect counts — *Validated: Eliminated correlated subqueries, 51× speedup*
- [x] **DB-02**: Add composite indexes for common query patterns — *Validated: 13 indexes covering all query patterns*
- [x] **DB-03**: Refactor house_cusps with normalized locations table — *Validated: Reduced redundancy, referential integrity*
- [x] **DB-04**: Create planet_positions hypertable with TimescaleDB — *Validated: 1-day chunks, 1-minute resolution*
- [x] **DB-05**: Create aspects hypertable for aspect data — *Validated: Efficient time-range queries*
- [x] **DB-06**: Create lunar_conditions hypertable for Moon data — *Validated: VoC and sign tracking*

### Data Loading (Phase 2)

- [x] **LOAD-01**: Implement ChunkManager with LRU cache — *Validated: O(1) access, configurable limits*
- [x] **LOAD-02**: Load data from database when available — *Validated: Fast cache hits*
- [x] **LOAD-03**: Generate data from Swiss Ephemeris when not in database — *Validated: Automatic fallback*
- [x] **LOAD-04**: Save generated data to database for future queries — *Validated: Background persistence*
- [x] **LOAD-05**: Background pre-fetching of adjacent chunks — *Validated: Reduced cache misses*

### Query System (Phase 3)

- [x] **QUERY-01**: Find optimal wedding dates (Venus aspects, Moon sign, no VoC) — *Validated: <100ms for 60-day ranges*
- [x] **QUERY-02**: Find void-of-course Moon periods — *Validated: Gap-and-island aggregation*
- [x] **QUERY-03**: Find planetary retrograde periods — *Validated: Shadow period detection*
- [x] **QUERY-04**: Find exact aspects within date range — *Validated: Orb and type filtering*
- [x] **QUERY-05**: Query completes in <100ms for 60-day ranges (cached) — *Validated: 45ms average achieved*

### Performance (Phase 4)

- [x] **PERF-01**: Multi-resolution storage (different intervals per planet) — *Validated: Continuous aggregates by body speed*
- [x] **PERF-02**: Memory usage <30MB for 30-day cache — *Validated: Soft limit with monitoring*
- [x] **PERF-03**: Database storage <50GB/year — *Validated: Aspect filtering achieves ~80% reduction*
- [x] **PERF-04**: Wedding query 51× faster than baseline (2.3s → 45ms) — *Validated: aspect_summaries JOIN*
